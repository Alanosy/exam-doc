# 阅卷与成绩

对应后端服务 `ruoyi-exam-mark` :9215（主观题）与 `ruoyi-exam-answer` :9214（客观题 + 成绩落库）。

## 判分全景

```text
考生交卷
    │
    ├──▶ 客观题（单选/多选/判断/填空）  → answer 服务即时判分
    │        结果三态：正确 / 半对 / 错误
    │
    └──▶ 主观题（简答/论述/代码/上传/匹配）
              │ answer 调 mark.syncSubjective 同步阅卷任务
              ▼
         教师人工阅卷 → mark 算分 → writeBackMark 回写 answer
              │
              ▼
         最终成绩写入 exam_record
```

::: tip 成绩只有一处写入口
主观题得分由 `mark` 通过 `writeBackMark` **回写**到 `answer`，其它服务不允许直接改成绩字段。
**排查成绩异常时，只需要盯这一条链路。**
:::

## 客观题：自动判分三态

不是简单的「对 / 错」，而是三态：

| 结果 | 触发条件 | 是否进错题本 |
| --- | :---: | :---: |
| 正确 | 完全答对 | ❌ |
| **半对** | 多选题漏选、填空题部分空答对 | ✅ |
| 错误 | 完全答错 | ✅ |

::: tip 为什么要有「半对」
多选题漏选说明「知道但不全」，和茫然无知是两回事。
两者都进错题本，但统计时可以区分——这是有价值的学情信号。
:::

能否得部分分，取决于试卷有没有开 `partial_score`（见 [试卷与组卷](/guide/paper#判分策略)）。

## 主观题：三级人工阅卷

导航路径：

```text
阅卷管理
   │
   ├── 按考试聚合列表（显示阅卷进度）
   │      点击某场考试
   │      ▼
   └── 答卷列表 exam_mark_task
             点击某份答卷
             ▼
       逐题打分 exam_mark_item
```

### 阅卷管理首页

按考试分组，每组显示进度条：

```text
前端期末考试          已阅 45 / 60  ████████████░░░░  75%
Java 认证考试         已阅 12 / 12  ████████████████  100%  ✓
```

100% 时进度条变成功色。

### 答卷列表

列出该考试下所有需要人工阅卷的答卷，标注是否已阅。

### 逐题打分

主观题按「考试 → 答卷 → 逐题」层层下钻。每道题显示：

- 题干
- 参考答案
- 考生作答（含富文本 / 代码 / 上传的附件）
- 该题分值上限
- 输入框、给分按钮

::: warning 未打分的题按 0 分计
点击「完成阅卷」时，如果有题还没打分，会提示「将按 0 分计」。
**这是不可撤销的**——完成阅卷后要改分只能走 rescore（也会留日志）。
:::

## 改分审计

每一次打分与改分都写 `exam_mark_log`，动作区分五种：

| 动作 | 含义 |
| --- | --- |
| `create` | 创建阅卷任务 |
| `score` | 首次打分 |
| `rescore` | 修改分数 |
| `ai` | AI 预评（当前未接入） |
| `finish` | 完成阅卷 |

每条日志记录：**谁、什么时候、哪道题、从几分改到几分**。

阅卷页提供「阅卷日志」抽屉，可随时回溯。

::: tip 前端表单用 Map 而非数组
答题得分表单在前端是 `Record<itemId, MarkScoreForm>` 而不是数组。
这样做是为了避免「题目顺序发生变化导致分数错位」——按 key 索引比按下标索引稳。
:::

## AI 预评（未接入）

页面上可能有「AI 预评」按钮。当前实现是 `DefaultMarkAiServiceImpl` 本地兜底，会返回「**未接入**」。

::: warning 这是已知状态，不是故障
Python Agent 已经实现了 AI 阅卷能力，Java 侧的接线工作进行中。
见 [考试微服务总览 — AI 服务](/backend/exam/overview#ai-服务-ruoyi-exam-ai-9220)。
:::

即使将来接入，设计上 AI 分也**不会自动生效**——只把建议分填进输入框，仍需教师点保存。教师的签字那一刻才是责任归属。

## 双评仲裁（预留）

「双人评阅 + 第三人仲裁」的接口已预留，但**当前尚未接入**，现在是单人阅卷模式。

## 成绩生效与后续

一份答卷完成阅卷后：

```text
① mark 计算主观题总分
② 调 answer.writeBackMark 回写
③ answer 更新 exam_record 总分
④ 如果及格且绑定了证书模板 → 触发 cert 颁发
⑤ 如果全部答卷阅完 → 可手动触发 stat 重算
```

::: tip 有主观题的卷子会延后发证
这是**故意的**。如果先发证后改分，证书上的成绩就和最终成绩不一致了。
所以 `exam-cert` 会等 `exam-mark` 完成后才发。
:::

## 作废答卷

如果某份答卷需要作废（比如发现作弊证据充分），可以在统计页把它标记为不入统：

```text
PUT /stat/exam/{examId}/record/{recordId}/exclude
```

作废后该答卷不计入统计，但记录本身保留，不物理删除。

## 常见问题

### 客观题为什么没自动出分

检查两点：

1. 试卷是不是关掉了「自动判分」开关 → 关了就全走人工
2. 这道题的题型是不是主观题（简答/论述/代码/上传/匹配）→ 这些本来就人工阅

### 改分了但考生看到的分没变

成绩回写是异步链路。等几秒刷新。如果一直不变：

- 检查 `mark` 服务是否在跑
- 看 `exam_mark_log` 有没有成功记录
- 可能是 `writeBackMark` 失败了，查 answer 服务日志

### 阅卷进度一直不满

有答卷还没阅完。列表页点进去看是哪些答卷待处理。

也可以**批量完成**——未打分的题按 0 分计。

### 想让几位老师分工阅同一场考试

当前版本是「一份答卷一个人阅完」，不支持按题目分工（流水线阅卷）。
多人协作只能按**答卷维度**分工，各自挑不同的答卷阅。
