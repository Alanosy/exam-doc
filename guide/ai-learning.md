# AI 学情与推题

考试结束不是终点。AI 能帮你看清**学生到底哪里没学会**，
并给每个人推不同的练习。

## 错题归因

学生做错一道题，原因可能完全不同：

| 错误类型 | 说明 | 该怎么补救 |
| --- | --- | --- |
| `concept` | 概念没理解 | 回去讲概念 |
| `calculation` | 计算出错 | 练计算，不是重讲概念 |
| `misread` | 审题失误 | 练读题，不是练知识点 |
| `incomplete` | 答得不完整 | 练表达的完整度 |
| `skill` | 技巧不熟练 | 专项训练 |
| `careless` | 粗心 | 一般不用专门补 |

**归因对了，补救才有效。**
把「审题失误」当成「概念不懂」去补课，是浪费时间。

### 怎么用

1. 进入学情分析，选学生或班级
2. 点「AI 归因」
3. 看输出的薄弱知识点、错误类型分布与优先级

输入是错题清单（题目、我的作答、正确答案、错过的次数），
输出：

| 字段 | 说明 |
| --- | --- |
| `weak_points[]` | 薄弱知识点，按严重程度排 |
| `error_distribution` | 错误类型分布（上表六类各占多少） |
| `priority[]` | 建议优先补什么 |
| `advice` | 总体建议 |

### 班级视角

对全班做归因，你能看到**错误类型的分布**：

```text
概念未理解   42%   ← 主要问题，说明课上这块没讲透
审题失误     28%   ← 需要专项训练读题
计算错误     18%
粗心         12%
```

这个分布比「平均分 72」有用得多——它直接告诉你**下一节课该讲什么**。

## 个性化推题

归因之后，给学生推该练的题。

### 推荐原则

提示词里定死了两条原则：

**1. 循序渐进**

不要一上来就推难题。先推同知识点的基础题建立信心，
再逐步加难度。

**2. 遗忘曲线**

错过的知识点要**间隔重复**——
今天错的题，过几天再练一次，比连续练十次有效。

### 参数

| 参数 | 说明 |
| --- | --- |
| 学情画像 | 来自归因结果 |
| 薄弱知识点 | 重点推这些 |
| 候选题池 | 从哪些题里挑 |
| 推荐数量 | 1 ~ 10 |

输出每条推荐带：

| 字段 | 说明 |
| --- | --- |
| `question_id` | 题目 ID |
| `reason` | **为什么推这道题** |
| `priority` | 优先级 |
| `target_point` | 针对哪个知识点 |

::: tip `reason` 字段很关键
推荐结果要能解释。
学生看到「因为你上次在『TCP 三次握手』上错了 2 次，
这道同知识点的题帮你巩固」，
比看到一堆随机题目更愿意练。
:::

### 一次别推太多

上限 10 道是硬限制。实践中**一次推 3~5 道**效果最好——
推太多学生反而不做。

## 学情画像

归因结果会写入**长期记忆**，逐渐形成每个学生的学情画像：

```text
学生：张三
薄弱知识点：TCP 三次握手（错 3 次）、子网划分（错 2 次）
已掌握：OSI 七层模型、IP 地址分类
错误倾向：审题失误偏多（35%）
```

画像会持续更新，下次归因和推题都会用到。
所以**用得越久，推荐越准**。

查看某个学生的画像：`GET /api/ai/recommend/profile/{user_id}`

::: tip 画像存在哪
存在 Redis（连不上时降级为内存）。
**长期画像没有过期时间**，短期记忆 30 分钟过期。

注意：如果 Agent 重启且没配 Redis，长期画像会丢。
生产环境建议配 Redis。
:::

## 学生的视角

学生自己也能用 AI：

| 我想…… | 怎么说 |
| --- | --- |
| 看我哪里没学会 | 「我哪些知识点比较薄弱」 |
| 复习错题 | 「把我的错题给我练一遍」 |
| 查考试成绩 | 「我这次考得怎么样」 |
| 问考试安排 | 「我最近有什么考试」 |

::: warning 学生看不到管理功能
学生的 AI 助手里**压根看不到**「给全班打分」「发布考试」这类能力，
不是靠 AI 自觉，而是这些工具不在给模型的清单里。

此外，即使学生试图让 AI 做越权操作，
网关会因为权限码不足返回 403。
:::

## 考生的权限边界

| 能力 | 教师 / 管理员 | 考生 |
| --- | --- | :---: |
| 出题 | ✅ | ❌ |
| 全班成绩分析 | ✅ | ❌ |
| 试卷审查 | ✅ | ❌ |
| 监考分析 | ✅ | ❌ |
| 看自己的错题 | ✅ | ✅ |
| 查自己的成绩 | ✅ | ✅ |
| 问考试安排 | ✅ | ✅ |
| 用 AI 自由问答 | ✅ | ✅ |

学生问「帮我出题」时，系统会转给通用流程按权限重新判断，
而不是报一个生硬的错误。

## 典型场景

### 场景一：期中考后补弱

```text
1. 对全班做 AI 归因 → 发现 42% 是概念问题，集中在「子网划分」
2. 下一节课重讲子网划分
3. 给掌握不好的学生推 5 道专项题
4. 两周后再归因 → 看是否改善
```

### 场景二：考前自适应复习

```text
1. 学生进入错题本
2. 系统基于画像推 5 道题（间隔重复 + 循序渐进）
3. 做错的题再次进入错题本，更新画像
4. 循环
```

### 场景三：发现异常

```text
某学生错误类型里 misread（审题失误）占 60%
→ 不是知识问题，是读题习惯问题
→ 针对性训练，而不是补课
```

## 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 归因太笼统 | 错题样本太少 | 至少 5~10 道错题再归因 |
| 推荐的题太难 | 候选题池里都是难题 | 扩大候选题池，让 AI 有得选 |
| 推荐重复 | 画像没更新 | 做完推的题后要重新归因 |
| 画像丢了 | 没配 Redis 且 Agent 重启 | 生产环境配 Redis |
| 学生看不到推题 | 权限或入口未开 | 检查角色配置 |
