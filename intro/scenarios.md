# 适用场景

砚考不是「又一个答题工具」，它面向的是**需要认真对待结果**的考试。
下面几个场景是它设计时就对标准的主力场景。

## 高校期末考试 / 补考 / 重修

| 痛点 | 砚考的应对 |
| --- | --- |
| 几千人同时在线，系统扛不住 | `exam-answer` 独立成库服务，可单独横向扩容；统计走预计算表而不是实时聚合 |
| 按教学班排考 | 考试准入支持**白名单按部门选人**，直接复用组织架构 |
| 要与教务系统对接 | 完整的 RESTful 接口，见 [API](/api/) |
| 缓考、违纪要走流程 | 阅卷意见与防作弊事件都可导出留档 |

**建议配置**：开启全部 9 项防作弊 + 摄像头抓拍；走网关 HTTPS + 证书留存至少一年。

## 职业资格与认证考试

这是防作弊要求最高的一类。

| 痛点 | 砚考的应对 |
| --- | --- |
| 代考 | 定时摄像头抓拍 + 入场核验 + 事件流水可回放 |
| 作弊 | 13 类行为检测，**服务端判定**强制交卷，前端改 JS 无效 |
| 成绩存档与证书发放 | 及格自动发证，支持证书编号、有效期、吊销与打印 |
| 考后追溯 | 每个作弊事件带时间戳，可按考生导出报告 |

**建议配置**：切屏上限设为 1~2 次即强制交卷；考试结束后保留抓拍照片至申诉期结束。

::: warning 摄像头要求 HTTPS
浏览器在非 localhost 环境下要求 **HTTPS** 才允许访问摄像头。认证考试必须在 HTTPS 下部署，见 [HTTPS 配置](/questions/https_config)。
:::

## 企业校招 / 社招笔试

| 痛点 | 砚考的应对 |
| --- | --- |
| 候选人分散，组织成本高 | **公开链接 + 加入码 + 密码 + 有效期**，一条链接发出去即可 |
| 限时答题 | 限时 + 迟到不允许入场 + 倒计时到点自动交卷（服务端兜底） |
| 需要防作弊报告 | 每次考试可导出作弊行为报告作为录用参考 |
| 与 ATS 集成 | [API](/api/) 提供成绩拉取接口 |

**建议配置**：用「练习」类型做笔试；关闭摄像头（带宽与隐私考量）但保留切屏与开发者工具检测。

## 内部培训与上岗考核

| 痛点 | 砚考的应对 |
| --- | --- |
| 岗位题库零散 | 题库按**分类树**组织，支持可见性与归档三态 |
| 要设达标线 | 试卷可配及格分，证书绑定达标才能拿 |
| 考完就忘 | **错题本**自动收录错题与半对题，支持反复重练、记笔记、标记掌握 |
| 培训效果难衡量 | 知识点掌握度分析，定位群体薄弱环节 |

**建议配置**：允许多次重考；开启答案展示（交卷后），让考核变成学习闭环。

## 日常作业与随堂测验

轻量使用：直接发一场「练习」类型考试，客观题自动判分即时反馈，不用配证书、不用配监考。

## 不太适合的场景

坦白说，砚考不是万能的：

| 场景 | 原因 |
| --- | --- |
| 纯问卷调研 | 没有跳转逻辑、没有问卷统计模型，用问卷工具更合适 |
| 需要编程上机评测（编译运行打分） | 代码题目前只做文本存储与人工阅卷，**不支持在线编译判分** |
| 万人同场检测仪实操考核 | 属于线下考务系统范畴 |
