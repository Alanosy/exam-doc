# 核心概念

砚考里最容易混淆的是**题库、试卷、考试**三者的关系。理清之后，后面的操作都会变得直觉。

## 层级关系

```text
题目 (Question)
  └── 属于 → 题库 (Question Bank)
                └── 被引用 → 试卷 (Paper)
                                └── 被使用 → 考试 (Exam)
                                                └── 产生 → 作答记录 + 成绩
```

用一句话概括：**题库是原料，试卷是配方，考试是一场具体的施测。**

| 概念 | 是否可复用 | 主要作用 |
| --- | --- | --- |
| 题目 | 是 | 最小粒度，可跨题库共享（引用而非复制） |
| 题库 | 是 | 按学科/课程组织题目，是权限分配的基本单位 |
| 试卷 | 是 | 一次组卷结果，可被多场考试复用 |
| 考试 | 否（可复制） | 绑定时间、对象、监考规则的具体场次 |

## 题目 Question

一道题目的完整信息包括：

- **题干与选项**：支持富文本、图片、音频、LaTeX 公式
- **答案**：客观题存标准答案，主观题存参考答案 + 评分要点
- **元数据**：题型、知识点、难度系数、认知层次、来源、审核状态
- **解析**：考后可向学生公布

::: tip 关于难度系数
砚考采用 **难度系数 = 该题平均得分 / 该题满分**，取值范围 0—1。
数值越大表示题目越容易。首次录入时可填经验值，
考试结束后系统会用真实作答数据回写校准。
:::

## 知识点 Knowledge Point

知识点是一棵树（如 `力学 → 动量与能量`），它同时服务于三个场景：

1. **组卷**：设定各知识点的题目占比，保证覆盖面
2. **分析**：计算班级/学生的知识点掌握度
3. **练习**：错题本按知识点归类，推送针对性练习

建议在建库初期就搭好知识点目录，后期补录成本较高。

## 试卷 Paper

试卷是「一组题目 + 分值/顺序规则」的组合。三种模式：

| 模式 | 题目来源 | 考生之间是否同卷 | 典型用途 |
| --- | --- | --- | --- |
| 固定卷 | 人工指定 | 完全相同 | 正式期末考、资格认证 |
| 抽题卷 | 规则随机抽取 | 同一场考试内相同 | 期中测验、月考 |
| 随机卷 | 规则随机抽取 | 每人不同 | 大规模机考、招聘笔试 |

注意：**抽题卷与随机卷的题目在开考时才真正确定**，
所以「试卷总分」在组卷阶段是预估的，开考后才会固化。

## 考试 Exam

考试 = 试卷 + 时间 + 对象 + 规则。状态流转如下：

```text
草稿 ──发布──▶ 未开始 ──到达开始时间──▶ 进行中 ──到达结束时间──▶ 已结束
  ▲                                                              │
  └────────────────────── 成绩发布 ◀─── 阅卷完成 ◀──────────────┘
```

- **草稿**：可反复修改，考生不可见
- **未开始**：已发布，考生可看到考试信息但无法进入
- **进行中**：考生可作答，监考生效
- **已结束**：停止作答，进入阅卷
- **成绩发布**：学生可查看成绩与解析

## 组织与角色 Organization / Role

砚考用一棵组织树描述机构结构（学校 → 学院 → 专业 → 班级，或 集团 → 公司 → 部门 → 小组）。
**权限是挂在组织节点上的**，这意味着某个管理员能看到的数据范围取决于他被授予了哪个节点。

内置角色见 [用户与角色](/admin/users-roles)。

## 任务 Task

阅卷、复核、仲裁这类需要分配给具体人的工作，在砚考里统一抽象为**任务**。
任务支持按题分配、按人分配、按考生分段分配，并自带进度看板。

详见 [阅卷与复核](/guide/grading)。
