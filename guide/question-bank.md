# 题库与试题

题库是砚考里最需要长期投入的部分。建得好了，后面每次出卷都省力。
对应后端服务 `ruoyi-exam-question` :9211。

## 题库分类

进入 **题库管理 → 题库分类**，先搭一棵分类树，再建题库。

```text
计算机学院
├── 前端开发
│   ├── HTML/CSS
│   ├── JavaScript
│   └── 框架
├── 后端开发
│   └── Java
└── 数据库
```

分类是树形结构，支持拖拽调整归属。

::: tip 分类怎么设计才好用
**按你将来怎么抽题来设计。** 如果经常要出「JavaScript 中等难度 5 道」，
那分类粒度就要具体到 JavaScript，而不是笼统的「前端」。

最常用的三种组织方式：

| 组织方式 | 适合 |
| --- | --- |
| 学科 → 章节 → 知识点 | 学历教育 |
| 岗位 → 技能项 | 企业培训 |
| 认证科目 → 模块 | 资格认证 |
:::

## 新建题库

| 字段 | 说明 |
| --- | --- |
| 题库名称 | 例如「JavaScript 基础」 |
| 分类 | 从分类树里选 |
| 可见性 | **私有**（仅自己）/ **公开**（同事可引用） |
| 状态 | 草稿 / 正常 / 归档（归档后不再参与随机抽题） |
| 描述 | 备注，团队协作用 |

## 试题管理

在题库列表点操作列的「试题」，进入该题库的题目列表，即可新增/编辑/导入/导出。

### 通用字段

| 字段 | 说明 |
| --- | --- |
| 题型 | 9 种，见下 |
| 题干 | 富文本，支持图片、公式、代码块 |
| 选项 | 单选/多选/判断题才有 |
| 参考答案 | 格式随题型不同，见下 |
| 解析 | 富文本，考生可在考后看到 |
| 难度 | `easy` / `medium` / `hard` |
| 默认分值 | 加入试卷时的默认分 |
| 知识点标签 | 用于知识点掌握度分析 |

### 9 种题型与答案格式

#### 单选 / 多选

参考答案用 `rightKeys` 数组：

```json
{ "rightKeys": ["A", "C"] }
```

选项可用富文本（放图片、代码块）。

::: tip 判断题很省事
选判断题型时，系统自动固定为「正确 / 错误」两个选项，不用手动填。
其它表现与单选题一致，判分也是自动的。
:::

#### 填空

支持**多空**，每空支持**多个等价写法**：

```json
{
  "blanks": [
    { "answers": ["张三"] },
    { "answers": ["Beijing", "北京"] }
  ]
}
```

考生只要答中其中任一写法即判对——适合「北京 / 北京市 / Beijing」这类情况。

::: warning 空格的问题
考生作答时首尾空格会被 trim，但字符串中间的空格不忽略。
像「中华人民共和国」这类答案，别在中间敲空格。
:::

#### 简答 / 论述

富文本参考答案，考生作答同样是富文本。**人工阅卷**。

#### 代码

```json
{
  "language": "java",
  "answer": "public class Main { ... }",
  "remark": "关键点说明"
}
```

支持的语言：

```text
java  python  cpp  c  csharp  go
javascript  typescript  sql  shell
```

::: tip 代码题用纯文本，不用富文本
答题页的代码题用 **textarea** 而不是富文本编辑器——富文本会破坏缩进，对程序员来说是灾难。
:::

#### 文件上传

题目本身配的是文本参考答案，考生上传附件作答，**人工阅卷**。

#### 匹配

```json
{ "pairs": [{ "left": "CPU", "right": "中央处理器" }] }
```

## Excel 批量导入

几百道题不要手工加。**列表页 → 导入 → 下载模板 → 按格式填 → 上传**。

### 模板里的 7 条格式说明

这些是模板自带的关键规则，第一次用务必读一遍：

| # | 规则 |
| --- | --- |
| 1 | 单选/多选题的答案，填「选项 A~F」形式的<｜hy_place▁holder▁no▁813｜>号（如 `A`、`AC`） |
| 2 | 判断题的答案填「正确」或「错误」 |
| 3 | 填空题**多个空用 `\|` 分隔** |
| 4 | 填空题**同一空的多个等价写法用 `;` 分隔** |
| 5 | 匹配题多个配对用 `;` 分隔，每项写「左项=右项」 |
| 6 | 难度填 `easy` / `medium` / `hard` |
| 7 | 题型必须是标准的 9 种之一 |

### 校验策略

::: warning 整批校验，失败整批回滚
任意一行格式不对，**整批都不会入库**，并且会逐行告诉你哪一行哪个字段有问题。
这不是 bug，是为了避免「一半题进来一半没进来」的脏数据。

数据量特别大时，建议拆成每批 200~500 行导入。
:::

### 导出

列表页点「导出」会导出当前筛选条件下的题目，方便离线批改后再导回。

## 常见问题

### 想批量换题库怎么办

列表页支持 **批量修改题库**（`changeQuestionBank`）操作，把选中的题整体迁移到另一个题库，
而不是逐个改——关联的 `paper_question` 不受影响。

### 题目被引用了还能改吗

可以改，但要注意：

- 已发布且**已开考**的考试：改了不影响，因为抓了快照
- 已发布但**未开考**的考试：改了会生效，可能导致前后考生题目不一致

**建议**：发布前锁定题库，或者用「归档」状态冻结。

### 导入失败怎么排查

看错误提示里的行号和字段名。最常见的是：

| 报错 | 原因 |
| --- | --- |
| 题型不合法 | 填了「单选题」而要求是 `SINGLE` 这类标准值 |
| 答案格式错误 | 判断题填了「对」而要求是「正确」 |
| 多个空未分隔 | 忘记用 `\|` |
