# 在线监考与防作弊

这是砚考投入最重的一块。对应后端服务 `ruoyi-exam-proctor` :9219 与前端 `useProctor` hook。

## 设计原则

::: tip 判定在服务端，前端只是传感器
前端的 `useProctor` **只负责把可疑动作报上去**。
计数、风险分级、是否强制交卷**全部由服务端算**。

这样做的好处很直接：**改浏览器 JS 绕不过去**。
前端被禁用，最多是不再记录，而不会让考生获得额外权限。
:::

同时，规则对考生**透明公开**——答题页会展示「已切屏 N 次 / 上限 M 次」。防作弊的目的不是抓人，是让人不敢作弊。

## 可以配置什么

在考试配置的第二步「防作弊」区域，共 9 项：

| 规则 | 说明 | 达到上限 |
| --- | --- | --- |
| `switchScreen` | 切屏 / 离屏次数 | 强制交卷 |
| `copyPaste` | 复制 / 剪切 / 粘贴次数 | 强制交卷 |
| `maxPaste` | 粘贴次数上限（细粒度） | 强制交卷 |
| `camera` | 是否开启摄像头抓拍 | — |
| `cameraInterval` | 抓拍间隔（秒） | — |
| `fullScreen` | 是否要求全屏 | — |
| `maxExitFullscreen` | 退出全屏次数上限 | 强制交卷 |
| `devtool` | 是否检测开发者工具 | 记风险 |
| `multitab` | 是否检测多标签页 | 记风险 |

::: danger 默认值是「只记录、不强制」
```ts
{ switchScreen: 0, copyPaste: 1, camera: 0, fullScreen: 0,
  cameraInterval: 60, maxPaste: 0, maxExitFullscreen: 0, devtool: 1, multitab: 1 }
```

值为 **`0` 表示不设上限**（仅记录不拦截）。

**要认真防作弊，必须显式设阈值。** 建议配置：

| 考试性质 | switchScreen | copyPaste | camera | maxExitFullscreen |
| --- | :---: | :---: | :---: | :---: |
| 随堂练习 | 不限 | 不限 | 关 | 不限 |
| 期末/内部考核 | 3 | 5 | 开 | 3 |
| 认证考试 | 1~2 | 0 | 开 | 1 |
| 社招笔试 | 3 | 不限 | 关 | 不限 |
:::

## 检测的 13 类行为

| 行为 | 怎么检测到 | 上报字段 |
| --- | --- | --- |
| 切屏 / 离屏 | `visibilitychange` + `blur`/`focus` + 3 秒定时兜底 | `switch_screen` |
| 复制 | `copy`（capture 阶段） | `copy` |
| 剪切 | `cut` | `cut` |
| 粘贴 | `paste` | `paste` |
| 右键菜单 | `contextmenu` | `contextmenu` |
| 开发者工具 | 组合键 + 窗口尺寸差 > 160px 二次判断 | `devtool` |
| 多标签页 | `BroadcastChannel` ping/pong | `multitab` |
| 进入全屏 | `fullscreenchange` | `enter_fullscreen` |
| 退出全屏 | `fullscreenchange` + 3 秒定时兜底 | `exit_fullscreen` |
| 摄像头拒权 | `getUserMedia` 失败 | 异常记录 |
| 摄像头抓拍 | 定时 / 事件触发 | `periodic` / `enter` / … |
| 心跳丢失 | 30 秒一次 | session 状态 |
| 交卷 | 提交 / 卸载 | `finish` |

::: warning 切屏检测的难点
很多人以为监听 `visibilitychange` 就够了。实际上——
**切到微信/钉钉这类其它应用窗口时，`document.hidden` 仍然是 `false`，只会来一个 `blur`。**

砚考的处理是「焦点状态机」：
状态一律现读（`document.hasFocus() && !document.hidden`），事件只决定「什么时候读」；
再配上「同一段离屏只记一次」和 1.5 秒节流去重；
最后在 `[0, 300, 1200]` ms 三个时间点延迟复读（Chrome 在 `blur` 回调里 `hasFocus()` 常常还是 true）。
:::

## 摄像头抓拍

| 环节 | 处理 |
| --- | --- |
| 分辨率 | 请求 640×480，存成宽 320 的 JPEG（质量 0.7） |
| 黑帧检测 | 隔点采样，平均亮度 < 6 直接丢弃（挡摄像头无效） |
| 等待 DOM | 最多等 10 秒（模板 `v-if` 导致开考瞬间 `<video>` 还没渲染） |
| 等待画面 | 最多等 8 秒到 `readyState >= 2`，否则拍出来全黑 |
| 保活重试 | 后台每 2 秒重试挂流，最多 15 轮；每 3 秒检查轨道是否 ended |

**抓拍时机**：入场 `enter`、周期 `periodic`（默认 60 秒）、离屏 `switch_screen`、回来 `resume`。

::: danger 摄像头必须 HTTPS
浏览器在非 `localhost` 环境下要求 **HTTPS** 才给摄像头权限。
本地开发看不出问题，部署到 HTTP 站点会直接失败。

配置见 [HTTPS 配置](/questions/https_config)。
:::

## 监考中心

菜单：**监考中心**（权限 `exam:proctor:list`）。三层下钻：

```text
① 考试分组列表
   └── ② 考生列表（抽屉）
          └── ③ 考生详情：事件流水 + 抓拍墙
```

### 实时性

默认开启 **10 秒静默轮询**（不是 WebSocket），没有明显 loading 提示，界面感觉是准实时的。可以选择关掉以省流量。

### 风险等级

| 等级 | 含义 | 颜色 |
| --- | --- | --- |
| `normal` | 正常 | 绿 |
| `suspect` | 可疑（有少量事件） | 橙 |
| `serious` | 严重（达到阈值） | 红 |

### 会话状态

```text
online        在线答题中
offline       掉线（心跳超时）
submitted     已交卷
force_submit  被强制交卷（违规超限）
```

超过限制的次数在列表里**标红**显示。

## 数据流向

```text
考生浏览器 useProctor
    │ ① 事件入队；队列 ≥ 5 条或每 5 秒 flush 一次
    ▼
POST /proctor/event/report
    │
    ▼
exam-proctor :9219
    │ ② 写 exam_proctor_event
    │ ③ 累加计数，对照该考试的规则判定
    │ ④ 达到上限 → 通知 exam-answer 强制交卷
    ▼
写 exam_proctor_session
```

::: tip 为什么批量上报而不是一条一发
一场百人考试如果每个事件都发一次请求，会给网关和 proctor 造成巨大压力。
批量 + 节流的设计把请求量降下来，代价是最多延迟 5 秒——对监考场景完全够用。
:::

## 给考生的体验

答题右侧有张监考卡片，实时显示：

```text
监考中
摄像头：已开启 / 未开启
已切屏：2 / 3 次
已粘贴：0 / 5 次
已退出全屏：0 / 3 次
已抓拍：12 张
```

达到上限时弹错误提示并自动交卷，文案由服务端返回。

## 免责与隐私

::: warning 合规提醒
摄像头抓拍涉及个人信息。正式启用前请：

1. 在考试须知里明确告知考生采集内容与用途
2. 遵守所在地区的数据保护法规（国内遵循《个人信息保护法》）
3. 设数据保留期限，过期删除抓拍原图
4. 抓拍图片不能被未授权的人看到（监考中心有权限控制）
:::

## 常见问题

### 考生说没作弊但被强制交卷

先看事件流水，确认是哪类事件触发的。常见误判来源：

| 现象 | 原因 |
| --- | --- |
| 切屏误报 | 双屏环境切换窗口会触发；或系统弹窗抢焦点 |
| 粘贴误报 | 地址栏粘贴被 capture 捕获 |
| 开发者工具误报 | 某些浏览器插件会改变窗口尺寸 |

**建议**：`switchScreen` 给到 2~3 次而不是 1 次，容忍偶然误报。

### 摄像头一直打不开

1. 是不是 HTTP 不是 HTTPS
2. 浏览器有没有授权（地址栏左边看权限图标）
3. 有没有其它软件占用了摄像头（视频会议软件）
4. 隐私里是不是把站点加入了黑名单

### 监考页看不到数据

确认考生真的进了答题页——**进入答题页后才创建监考会话**。只加了考试没开考是不会有数据的。
