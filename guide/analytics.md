# 成绩与学情分析

对应后端服务 `ruoyi-exam-stat` :9216。这是砚考里唯一「重查询」的服务，独立部署就是为了不拖垮 OLTP。

## 入口

菜单：**考试统计**（权限 `exam:stat:*`）。两层：

```text
① 统计大盘（所有考试）
      点击某场考试
      ▼
② 单场考试详情（Tab 懒加载）
      ├── 概览
      ├── 考生明细
      ├── 试题分析
      └── 知识点分析
```

## 一、大盘概览（Dashboard）

全局视角，适合管理者看整体：

| 指标 | 说明 |
| --- | --- |
| 考试场次 | 统计周期内的场次数 |
| 参考人次 | 有效答卷数（已排除作废） |
| 平均分 | |
| 及格率 | |
| **分数段分布** | 直方图 |
| 及格率 TOP | 按考试排行的及格率条形图 |

## 二、单场考试概览（Overview）

进入某场考试后先看这个 Tab：

- 应考 / 实考人数
- 最高分、最低分、平均分
- 及格人数与及格率
- 分数段分布
- 主观题阅卷进度（未完成会提醒）

## 三、考生明细（User）

列出每个考生的成绩与排名，支持三种筛选：

| 筛选 | 用途 |
| --- | --- |
| 全部 | |
| 只看错题 | 快速定位错题率高的考生 |
| 只看主观题 | 人工阅卷 / 复核 |

点击某个考生可以看他的**完整答卷明细**：每道题的作答、正确答案、得分。

## 四、试题分析（Question）

**最有教学价值的一张表**。左列表右详情：

| 指标 | 含义 | 怎么看 |
| --- | --- | --- |
| **正确率** | 答对人数 / 作答人数 | 太低说明题太难或讲得不好；太高说明区分度差 |
| **难度** | 通常用得分率表示 | 0.3 以下偏难，0.9 以上偏易 |
| **区分度** | 高分组与低分组在该题上的得分差 | 越低越不能区分学生水平 |
| **选项分布** | 每个选项被选的比例 | 某个错误选项特别集中 → 典型误解点 |
| **易错项** | 被选最多的错误选项 | 讲评重点 |

::: tip 怎么看出一道题是好题

| 难度 | 区分度 | 评价 |
| --- | --- | --- |
| 0.5 左右 | > 0.3 | ✅ 优秀 |
| 0.3~0.7 | 0.2~0.3 | 良好 |
| 0.3~0.7 | < 0.2 | ⚠️ 区分度不足 |
| < 0.2 或 > 0.9 | 任意 | ❌ 太难或太易，建议替换 |

一个典型场景：某题正确率 85%，但区分度只有 0.05，
说明**好学生坏学生都会做**——这道题对选拔毫无价值，但对考察基础点有用。
:::

## 五、知识点分析（Knowledge）

基于题目的知识点标签，输出每个知识点的掌握度，并做薄弱分级。

```text
| 知识点        | 掌握度 | 分级 |
|--------------|-------|------|
| 闭包           | 42%   | 薄弱 ⚠️ |
| 原型链         | 51%   | 薄弱 ⚠️ |
| ES6 语法       | 78%   | 一般 |
| DOM 操作       | 91%   | 掌握 ✅ |
```

点击某个知识点可以下钻：**哪些学生最该补这块**。

::: tip 这一页怎么用
不要只看全班平均。**先看薄弱知识点 → 下钻到人 → 定向推送练习**。
这才是从「考试」到「教学改进」的闭环。
:::

## 重算机制

砚考的统计**不是实时算的**，而是基于预计算汇总表（`stat_exam_*`）。

### 为什么这么设计

一场万人考试，如果每次打开统计页都全量聚合一次 `exam_answer`，数据库会被拖垮。
砚考的做法是：

1. 交卷/阅卷完成后写入/更新汇总表
2. `StatCalcScheduler` **每 10 分钟定时重算**兜底（防止漏触发）
3. 提供**手动重算**接口给着急的场景

### 何时需要手动重算

| 场景 | 需要手动重算 |
| --- | :---: |
| 刚改完主观题分数，想立刻看新统计 | ✅ |
| 刚作废了某份答卷 | ✅ |
| 数据看着不对 | ✅ |
| 正常浏览 | ❌ |

::: tip 数据不对先重算
手动重算是排查数据异常的第一步——大部分「分数对不上」的问题重算一次就好了。
:::

## 作废答卷

某份答卷不影响统计（如发现严重作弊、或重复提交的脏数据）：

```text
PUT /stat/exam/{examId}/record/{recordId}/exclude
```

作废后：

- 该答卷**不计入**所有统计
- 记录本身保留，不物理删除
- 可以取消作废

## 导出

统计结果支持导出。导出走异步任务表 `stat_export_task`。

::: warning 统计大盘的导出还没做
`stat/dashboard` 页的导出按钮目前提示「导出功能将在导出中心提供」。
单场考试的各 Tab 导出是可用的。
:::

## 数据流向

```text
exam-answer (exam_record/exam_answer)
exam-question (question)
        │ 只读拉取
        ▼
exam-stat
        │ 影子实体（QuestionRef / ExamRef / PaperQuestionRef）本地映射
        ▼
stat_exam_* 预计算表
        │
        ▼
   前端展示
```

::: tip 为什么用「影子实体」
`exam-stat` 用的是自己定义的 `QuestionRef`、`ExamRef` 等**只读影子实体**，
而不是直接依赖其它服务的领域对象。这样避免了跨库 JOIN，也避免了模块间强耦合。
:::

## 性能建议

| 场景 | 建议 |
| --- | --- |
| 万人级考试 | 给 `exam-stat` 单独扩实例，加大堆（1~2 GB） |
| 重算任务慢 | 避开考试高峰；或按考试分批重算 |
| 统计页加载慢 | 检查 `stat_exam_*` 表索引；考虑归档历史数据 |
| 查询统计服务超时 | Dubbo 默认 3 秒超时，重查询接口需放大 |

详见 [服务间调用 — 超时与重试](/backend/exam/invocation#超时与重试)。
