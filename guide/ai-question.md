# AI 出题与质检

命题是最耗时的环节，也是 AI 最能帮上忙的地方。
这一页讲怎么用 AI 出题，以及**怎么判断 AI 出的题能不能用**。

## 智能出题

### 操作步骤

1. 进入题库，点「AI 出题」
2. 填参数
3. 预览生成的题
4. 勾选要留的，入库（草稿态）
5. 检查后启用

### 参数说明

| 参数 | 说明 | 建议 |
| --- | --- | --- |
| 知识点 | 要考什么。多个用逗号分隔 | **越具体越好**。「TCP 三次握手」比「计算机网络」出得好 |
| 题型 | 单选/多选/判断/填空/简答/论述/代码等 | — |
| 难度 | 简单 / 中等 / 困难 | 默认中等 |
| 题数 | 1 ~ 30 | 一次别超过 10 道，多了容易雷同 |
| 默认分值 | 每题几分 | — |
| 参考资料 | 有教材或讲义可以贴进来 | **强烈建议用**，基于资料命题质量明显更高 |

### 提高出题质量的三个技巧

**1. 知识点写具体**

```text
❌ 计算机网络
✅ TCP 三次握手的报文顺序
```

前者 AI 会泛泛出题，后者能出到点上。

**2. 用参考资料**

把教材章节、讲义片段贴进「参考资料」，AI 会**优先基于资料命题**。
这是提升质量最有效的一招，也避免出现超纲内容。

**3. 一次别出太多**

一次 5~10 道。出 30 道的话，后半段会和前半段高度雷同。

需要大量题目时，分批出、换几个角度描述知识点，
或者用下面的**试题改写**做等价扩量。

### 生成结果的答案格式

AI 生成的答案按题型有不同的结构，与系统落库格式严格一致：

| 题型 | 答案格式 |
| --- | --- |
| 单选 / 多选 | `{"rightKeys": ["A", "C"]}` |
| 判断 | `{"rightKeys": ["A"]}`（A=正确，B=错误） |
| 填空 | `{"blanks": [{"answers": ["北京", "北平"]}]}` |
| 匹配 | `{"pairs": [{"left": "CPU", "right": "中央处理器"}]}` |
| 简答 / 论述 | `{"answer": "..."}` |
| 代码 | `{"language": "java", "answer": "...", "remark": "..."}` |

::: tip 填空题支持多个等价答案
`["北京", "北平"]` 表示两个答案都算对。
出填空题时注意让 AI 把常见的等价写法都列上。
:::

## 生成后：质检

**生成的题不要直接用，先过一遍质检。**

质检会检查这些：

| 检查项 | 说明 |
| --- | --- |
| 答案唯一性 | 多选题是否真的只有一个正确组合？会不会有第二个选项也说得通 |
| 题干歧义 | 表述是否含糊，是否用了「可能」「通常」这类词 |
| 暗示泄露 | 某道题的题干里是否直接给了另一道题的答案 |
| 干扰项质量 | 干扰项是否真的有迷惑性，而不是一眼假 |
| 难度匹配 | 标注「困难」的题是不是真的难 |
| 题目重复 | 这批题之间有没有重复或互相暗示 |

质检输出：

- `passed` —— 是否通过
- `quality_score` —— 质量分（0~10），**6 分以下不建议入正式库**
- `issues[]` —— 问题清单，每条含 `level`（minor/major）、`type`、`detail`、`suggestion`
- `summary` —— 一句话总结

::: warning 质检本身也会出错
质检是一条模型调用，它可能误判。
**质检通过 ≠ 可以用**，尤其主观题仍建议人工过一眼。

反过来，单题质检异常时系统会**按可用处理**（不至于因为质检挂了就废掉一道好题）。
:::

### 生成 + 质检一步到位

勾选「生成后质检」，系统会自动：

```text
生成 N 道 → 逐题质检 → 通过的 accepted，未过的 rejected
```

你在结果页能直接看到三类：通过的、被拒的（带原因）、质检记录。

这是**推荐的默认用法**——Reflection 只需额外一次调用，
就能拦掉大部分低级错误。

## 干扰项生成

给一道已经有正确答案的题，生成有迷惑性的干扰项。

| 参数 | 说明 |
| --- | --- |
| 题干 | — |
| 正确选项 | 键（如 A）与内容 |
| 已有选项 | 可选，避免生成重复的 |
| 生成数量 | 1 ~ 4 |

输出每个干扰项带一个 `trap` 字段，说明**这个选项的陷阱点在哪**：

```text
B. 四次挥手    trap: 混淆连接建立与连接拆除的过程
```

你可以据此判断干扰项合不合理。

::: tip 好的干扰项长什么样
好的干扰项是「**有迷惑性但可证伪**」——
它抓住的是学生的典型误解，而不是单纯的错。

提示词里明确禁止用「以上都不对」「以上都是」这类凑数项。
:::

## 试题改写扩量

把一道题变成几个**等价变体**，用于题库扩量与防泄露。

四种策略：

| 策略 | 说明 | 适用场景 |
| --- | --- | --- |
| `change_scene` | 换场景 | 「小明买苹果」→「某工厂采购原料」，考的是同一个知识点 |
| `change_number` | 换数字 | 计算题改数值，防止背答案 |
| `reverse` | 反向提问 | 「下列说法正确的是」→「下列说法错误的是」 |
| `deeper` | 加深层次 | 从「是什么」到「为什么」 |

一次可生成 1~10 个变体。

::: tip 防泄露的正确用法
同一场考试里放同一知识点的不同变体，
能显著降低「左右互看」的有效性。
:::

## 知识点打标

给**存量试题**批量补标签，适合题库建了很久、标签混乱的情况。

输出：

| 字段 | 说明 |
| --- | --- |
| `knowledge_points` | 知识点列表 |
| `difficulty` | 难度 |
| `cognitive_level` | **布鲁姆认知层次**（记忆/理解/应用/分析/评价/创造） |
| `confidence` | 置信度 |

认知层次这个字段很实用：
如果一份卷子全是「记忆」层的题，那它考查的深度就不够。

## 解析生成

为已有答案的题批量写解析，输出 `analysis` + `key_steps`（关键步骤）。

适合场景：老题库里只有答案没有解析，学生做完不知道为什么错。

## 试卷审查

出完卷子，让 AI 检查一遍：

| 检查项 | 说明 |
| --- | --- |
| 知识点覆盖 | 覆盖面够不够，有没有重复考同一个点 |
| 难度分布 | 是不是全是难题或全是送分题 |
| 重复度 | 有没有实质重复的题 |
| 预计用时 | 学生大概要多久，考试时长够不够 |
| 分值合理性 | 高分值的题是不是真的配得上这个分 |
| 题型结构 | 客观题与主观题比例是否合理 |

输入：试卷标题、时长、及格分、题目清单。
输出：`verdict`（结论）、`difficulty_distribution`、`knowledge_coverage[]`、`issues[]`、`suggestions[]`。

::: warning 审查对象是题目清单，不是考试
审查的是「这张卷子出得好不好」，
不包含「这场考试考得怎么样」——后者看 [成绩与学情分析](/guide/analytics)。
:::

## 难度预估

考前预估平均分、通过率与分数分布。

输入多了 `audience`（考生群体，默认「全体考生」）与 `history`（历史数据）。

输出的是**区间不是单点**，因为预估本来就不可能准。
当成参考，别当承诺。

## 用对话的方式出题

除了点按钮，也可以直接跟 AI 助手说：

```text
帮我出 10 道计算机网络的选择题，难度中等，放进测试题库
```

它会：

```text
1. 查题库找「测试题库」        → 找到了
2. 生成 10 道题                → 完成，展示预览
3. 等你确认                    → 「确认入库」
4. 批量写入（草稿态）           → 完成
```

如果「测试题库」不存在，它会问你是选别的库还是新建一个。
如果找到多个名字像的，会列出来让你选。

::: tip 缺什么一次问完
Agent 会**一次性把所有缺的参数问完**，而不是一轮问一个。
你填完就能直接跑，不会反复被弹回同一张卡。
:::

## 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 出的题高度雷同 | 一次生成太多 | 分批，每次 5~10 道，或换角度描述知识点 |
| 出的题超纲 | 没给参考资料 | 把教材/讲义贴进「参考资料」 |
| 多选题答案不唯一 | 表述不够严谨 | 用质检查「答案唯一性」，或人工复核 |
| 填空题判分太严 | 等价答案没列全 | 在答案里补等价写法 |
| 生成很慢 | 题数多 / 模型慢 | 正常现象，10 道约 8~15 秒 |
| 质检全拒 | 阈值偏严或提示词不匹配 | 看 `issues` 的具体原因，多数是表述问题 |
